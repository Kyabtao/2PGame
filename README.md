# 2PGame — 100 two-player browser games

One hundred local two-player games (same device, same keyboard or touch screen) built with plain HTML, CSS and JavaScript. No frameworks, no build step, no network calls — open `index.html` and play. Every game keeps a persistent scoreboard in the browser's `localStorage`.

- **100 games** across five categories: board & strategy, arcade & action, sports & reflex, cards & dice, brain & party.
- **Interactive screen for every game** — canvas action games, SVG boards, DOM card tables, with keyboard *and* touch controls (an on-screen pad appears on phones/tablets).
- **Scores saved in the browser** — series wins, draws, streaks, personal bests and match history, all per game, all in `localStorage`. Nothing leaves the device.
- **Everything connected** — a hub (`index.html`) lists, searches and filters all games; every game links back to the hub; player names set once are used everywhere.
- **Shared assets** — one design system (`assets/css/base.css`) and one game engine (`assets/js/core.js`) power all 100 games. A typical game is a single ~60–150 line `game.js`.

## Quick start

The site is fully static. Because browsers restrict some features on `file://` URLs, serve the folder with any static server:

```bash
# Python (installed almost everywhere)
python3 -m http.server 8080
# or, with Node installed
npx serve .
# or via the npm script
npm start
```

Then open <http://localhost:8080/>. Type both player names once on the hub, pick a game and play.

> To play on a phone/tablet, open the same URL from the device on your local network — touch controls appear automatically (the 🎮 button in a game's top bar toggles them).

## How it fits together

```
index.html ──loads──▶ assets/js/games.js (manifest)  ◀──loads── games/<id>/index.html
     │                assets/js/core.js  (engine)                     │
     │                assets/js/hub.js                                └── games/<id>/game.js  →  Game.init({...})
     │
     └── links to games/<id>/index.html ; every game's top bar links back to ../../index.html
```

- **`assets/js/games.js`** is the single source of truth. The hub renders from it, `tools/build.js` generates the per-game shells from it, and the engine reads the game's title/emoji from it.
- **`assets/js/core.js`** renders the common shell around every game (top bar with back link, rules, sound and touch-pad toggles, restart; the scoreboard with editable names and series wins; the stage; the hint footer) and provides the API games use.
- **Scores** live in `localStorage` under keys prefixed `2pgame:`. `Store.record(id, winner, detail)` is called by the engine whenever a game ends with `g.win()` / `g.draw()`. The hub's **History** button shows and exports everything as JSON; **Reset** wipes it.

### Local storage layout

| Key | Contents |
|-----|----------|
| `2pgame:players` | `["Player 1 name", "Player 2 name"]` |
| `2pgame:settings` | `{ sound, pad, … }` and per-game preferences |
| `2pgame:score:<game-id>` | `{ w: [p1Wins, p2Wins], d: draws, n: gamesPlayed, last: [ …recent results ], streak: { p, n }, best: { key: { v, p } } }` |

## Controls

Every game shows its own rules and controls in the **?** dialog (also shown before the first round). Conventions used throughout:

| | Player 1 (red) | Player 2 (blue) |
|---|---|---|
| Move | `W` `A` `S` `D` | Arrow keys |
| Action / fire | `E` (secondary `Q`) | `/` (secondary `.`) |
| Mash / buzz | `Q` | `P` |
| Choices 1–4 | `1` `2` `3` `4` | `7` `8` `9` `0` |
| Any game | `Enter` / `Space` start or play again · `R` restart · `Esc` close dialogs |

Turn-based games are played with the mouse or by tapping. Hidden-information games (Battleship, Go Fish, Hangman…) use a **pass-the-device** screen between turns.

## Adding a new game

1. Add an entry to `assets/js/games.js`:
   ```js
   { id: 'my-game', title: 'My Game', emoji: '🎮', cat: 'arcade', mode: 'realtime', desc: 'One line about it.' }
   ```
2. Run `node tools/build.js` — it creates `games/my-game/index.html` and tells you `game.js` is missing.
3. Create `games/my-game/game.js`:
   ```js
   (function () {
     let starter = 1;                       // alternate who starts each round
     Game.init({
       id: 'my-game',
       rules: ['First to three points wins.'],
       controls: { p1: '<kbd>Q</kbd> to score', p2: '<kbd>P</kbd> to score' },
       points: true,                        // show live round points on the scoreboard
       onStart(g) {                         // build one round inside g.stage (cleared for you)
         const pts = { 1: 0, 2: 0 };
         g.key('KeyQ', () => score(1));
         g.key('KeyP', () => score(2));
         function score(p) {
           pts[p]++; g.points(pts[1], pts[2]); g.sfx('score');
           if (pts[p] === 3) { starter = 3 - starter; g.win(p, `${pts[1]} – ${pts[2]}`); } // recorded in localStorage
         }
         g.turn(starter, 'Press your key!');
       },
     });
   })();
   ```
4. Open `games/my-game/` in the browser, or run `node tools/smoke.js my-game`.

### Engine API cheat-sheet (`assets/js/core.js`)

| Call | Purpose |
|------|---------|
| `Game.init({ id, rules, controls, points, pad, onStart(g), onStop })` | Register the game. `pad` describes on-screen touch buttons that emit key codes. |
| `g.stage`, `g.name(p)`, `g.color(p)`, `g.other(p)`, `g.over` | Stage element, player names/colours, round state. |
| `g.turn(p, html)`, `g.status(html)`, `g.points(a, b)` | Update the scoreboard/status line. |
| `g.win(p, detail)`, `g.draw(detail)` | End the round; records the result in `localStorage`, shows the result dialog. |
| `g.key(codes, fn, {repeat, up})`, `g.down(code)` | Key handlers (auto-removed at round end) and polling for real-time games. |
| `g.loop(fn(dt))`, `g.after(ms, fn)`, `g.every(ms, fn)`, `g.countdown(3)`, `g.pass(p, text)` | Timing helpers, all cleaned up at round end. |
| `g.best(key, value, p, lower)`, `g.getBest(key)` | Personal-best tracking (e.g. fastest reaction time). |
| `g.modal({...})`, `g.toast(text)`, `g.sfx(name)` | Dialogs, toasts and synthesised sound effects. |
| `UI.grid`, `UI.canvas`, `UI.pointer`, `UI.deck`, `UI.card`, `UI.die` | Board grids, HiDPI canvas + pointer mapping, playing cards, dice. |
| `h(tag, attrs, ...children)`, `rnd`, `pick`, `shuffle`, `clamp`, `sleep`, `esc`… | Small DOM and maths helpers exposed globally. |

## Development

```bash
npm install          # only needed for the smoke test (installs jsdom)
npm run build        # regenerate game shells, report missing/orphan games and syntax errors
npm test             # build check + headless smoke test of all 100 games (~10 minutes)
node tools/smoke.js chess pong   # smoke-test specific games; VERBOSE=1 for console output
```

The smoke test loads each game page in jsdom, starts a round, fires a few hundred random key presses and clicks, and fails on any uncaught error or empty stage. Canvas rendering is stubbed, so visual checks still need a real browser.

## Deploying to GitHub Pages

The project is a plain static site with only relative links, so it works from a repository sub-path (`https://<user>.github.io/2PGame/`) without any configuration or build step. Two ways to publish:

**Option A — deploy from a branch (simplest, no files to add).**
1. Get the code onto `main` (merge this branch).
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, branch `main`, folder `/ (root)`, **Save**.
3. After a minute the site is live at `https://<user>.github.io/2PGame/`. `.nojekyll` is included so GitHub serves the files as-is.

**Option B — GitHub Actions (verifies the games before each deploy).**
1. Copy `tools/deploy/github-pages.workflow.yml` to `.github/workflows/pages.yml` (GitHub UI: *Add file → Create new file*, paste the contents).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Every push to `main` now runs `node tools/build.js` (manifest/syntax check) and publishes. The URL is shown in the workflow summary.

Notes:
- Scores are stored in each visitor's browser `localStorage`, scoped to the Pages origin, so nothing needs a server.
- Sound uses the Web Audio API and starts after the first tap/click, as browsers require.
- The site works unchanged on any other static host (Netlify, Vercel, Cloudflare Pages, S3, or a USB stick with a local server).

## Browser support

Any evergreen browser (Chrome, Edge, Firefox, Safari — desktop and mobile). Uses ES2020, CSS custom properties, `color-mix()`, Pointer Events and the Web Audio API for sound (sound can be muted from the top bar).
